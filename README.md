# AR Time-Capsule Cards

One physical card design, used for every guest. Each guest gets their own QR
code. Scanning it opens a page that asks for camera permission, then plays
that guest's personal video message directly on top of the printed card —
no app install, just the phone's browser.

## How it works

1. Every card has the same printed artwork on the front — that artwork is
   what the camera learns to recognize (the "target image").
2. Each guest's QR code encodes the same URL with two different query
   parameters: their name, and the filename of their video.
3. Scanning the QR opens `index.html`, which shows the guest's name and a
   "Start the camera" button (the browser needs a tap before it's allowed
   to ask for camera access).
4. Once the camera is pointed at the card, MindAR recognizes the artwork
   and anchors an invisible plane to it. That plane plays the guest's video.
5. Move the phone away and the video pauses; point it back and the video
   resumes from the start.

## What you'll need

- One card design, used for every guest (any birthday-themed image).
- One short personal video per guest.
- Python 3, to run the QR generator.
- Free HTTPS hosting for the page — GitHub Pages is the easiest option,
  since camera access only works over HTTPS (or `localhost`).

## 1. Design the card

Detailed, busy artwork tracks far more reliably than a plain color block or
mostly-empty design with just text — MindAR is matching visual texture, not
reading text. A photo collage, a detailed illustration, or a patterned
background all work well. Avoid large flat areas and symmetric patterns
(they're easy for the tracker to confuse with themselves).

**A ready-made starting point is included:** `target-card.png` (and its
source `target-card.svg`), generated by `make_target_card.py`. It's built
specifically to track well — asymmetric candle heights, striped texture,
and scattered ember detail spread across the whole frame rather than
concentrated in the middle.

- Use it as-is, or tweak `make_target_card.py` (colors, candle count, text)
  and re-run `python make_target_card.py` to regenerate it.
- If you'd rather have an AI image generator make a more illustrated or
  photoreal version, see "Generating the artwork with an AI image tool"
  below for a prompt written with the same tracking constraints in mind.
- **Keep the QR code off this artwork.** All guests share this one image,
  but each guest's QR is different — print it on the back of the card, or
  as a separate tag, rather than baking it into the front design.

### Generating the artwork with an AI image tool

If you want to try Midjourney, DALL·E, Stable Diffusion, or similar
instead, this prompt bakes in what MindAR needs (dense, asymmetric,
non-repeating detail) alongside the card's look:

> A birthday greeting card illustration, flat vector art style, dark warm
> charcoal-brown background. Seven lit candles of clearly different
> heights and widths in a row, off-center, each with warm gold and cream
> horizontal stripes and a small glowing flame. Hundreds of tiny scattered
> gold, cream, and ember-orange specks of varying size and opacity spread
> unevenly across the entire background, denser in some areas than others.
> A few small five-pointed stars tucked into the corners at random angles.
> The words "Happy Birthday" in an elegant serif typeface near the top.
> No symmetry, no repeating patterns, no large flat empty areas — rich,
> uneven texture across the full frame. Landscape orientation, 16:9.

Whatever you generate, run it through the same eye test: does every
region of the image have *something* distinct going on, with nothing
mirrored or tiled? If a region is flat or repeats, tracking will be
weaker there.

## 2. Compile the tracking target

MindAR needs your card image compiled into a `targets.mind` file:

1. Go to the free online compiler: https://hiukim.github.io/mind-ar-js-doc/tools/compile/
2. Upload your card image (`target-card.png`, or your own final artwork).
3. Download the resulting `targets.mind`.
4. Put it in this folder, next to `index.html`.

## 3. Record the videos

- Keep each clip well under a minute and compress it (aim for roughly
  5–15 MB) so it loads quickly on party wifi or mobile data.
- Name the files consistently and simply, e.g. `amara.mp4`, `kavi.mp4`.
- Put them all in the `videos/` folder.

## 4. Match the video's aspect ratio

In `index.html`, the `<a-video>` element has `width` and `height`
attributes that set the shape of the video plane. Measure your printed
card's width-to-height ratio and set these to match, or the video will
look stretched. The default (`width="1.8" height="1"`) assumes a roughly
1.8:1 landscape card.

## 5. Fill in the guest list and generate QR codes

Edit `guests.csv` (a sample is included):

```csv
name,video
Amara,amara.mp4
Kavi,kavi.mp4
```

Then run:

```bash
pip install "qrcode[pil]" --break-system-packages
python generate_qr.py guests.csv --base-url https://yourname.github.io/ar-cards/
```

This writes one PNG per guest into `qr_codes/`.

## 6. Host it

Push this whole folder — `index.html`, `targets.mind`, `videos/` — to a
GitHub Pages repository (or any static HTTPS host). GitHub Pages is free
and gives you HTTPS automatically, which the camera API requires.

## 7. Print and test

Print each guest's QR code onto or next to their card. Scan one yourself,
end to end, before the party — including on an iPhone if any guests will
be using one, since Safari is the strictest about camera and autoplay
permissions.

## Troubleshooting

- **Camera won't start at all** — the page must be served over HTTPS (or
  opened as `localhost`); it won't work from a plain `file://` path or
  over unencrypted HTTP.
- **Video plays but with no sound on iPhone** — this is expected on first
  load; the page falls back to muted playback and shows a "tap to turn
  the sound on" prompt automatically.
- **Card isn't recognized** — check the target was compiled from the
  exact final artwork, in good lighting, held roughly parallel to the
  phone and filling a reasonable portion of the frame.
- **Video looks stretched** — revisit step 4 and match the aspect ratio.

## A note on privacy

If you host this on a public GitHub Pages repo, the video files are
technically reachable by anyone who guesses or finds the URL, even though
none of the pages are linked from anywhere public. For a small private
party this is usually a reasonable trade-off, but avoid including anything
in a guest's video you wouldn't want to be a public link.
